# 多卡台接入方案

> **产品决策已更新（2026-08-27）。** 新码不再「发码选一台、兑换永不换台」。目标模型见 **[本站统一发码 · 双卡台绑定设计](本站统一发码-双卡台绑定设计.md)**：对外发 `DN-` 本站码，生成时预购 A 码 + B 码，兑换优先 A，A 挂了用 B。
>
> **本文下列「兑换 / 查单 / 禁用绝不换台」只约束 legacy 原生码**（`GPTD-` / `SXC-` / `AVF-` 透传，无 binding）。不要把旧 P2「发码按优先级选一台」当成新本站码的目标。
>
> 对照：Avanfinity Developer API 2026-08-01（`avanfinity-openapi.json`）与现网 `backend/internal/cardplatform`。

> 库存同步（本站→二级）是另一条线，见 `docs/代理购卡库存同步-对接说明.md`。双绑落地后 `issued_codes` 改为本站码，webhook 形状不变。

## 结论

这是**同一产品族的协议升级**，不是两家无关卡台。现网已经指向 Avanfinity 域名，只是走旧 SpaceX 风格 OpenAPI（`/openapi/v1` + `X-API-Key`）。2026-08-01 文档换了鉴权、路径、ID、码格式、验签和扣费语义，必须当**两个协议适配器**接。

**推荐形态（协议层，仍成立）：协议 adapter + 账户表。**

- **Legacy 原生码**：公开兑换按前缀选协议（`AVF-` → 新，`SXC-` / `GPTD-` → 旧），兑换不换台。
- **新本站码 `DN-`**：发码时 A+B 都买；兑换走绑定表，A 不可达才用 B。见绑定设计。
- 不要复制两套 fulfill，不要新开「卡台接入 2」，不要让主站替二级扫库存。

## 协议差异（原文）

| 点 | 旧（现网 client.go） | 新（OpenAPI 2026-08-01） |
| --- | --- | --- |
| 根路径 | `/openapi/v1` | 鉴权接口 `/api/v1` |
| 鉴权 | `X-API-Key` | `X-App-Id` + `X-App-Secret` |
| 发码 | `POST /gpt-direct/cdks` | `POST /gpt-direct/cdks/generate` |
| Body | `plan, count, funding_confirmed, preferred_*` | `plan, quantity, forceNewCard`（`additionalProperties=false`） |
| 扣费 | 发码扣套餐服务费 | **生成时不扣套餐费**；`forceNewCard` 的开卡费由生成者承担 |
| 完整码 | 响应里一次；之后列表可见前缀 | 成功响应 + **约 2 分钟**同键重放；之后 `code=null` |
| 列表 | 分页，真 `code_prefix` | 最多最近 100 条；`codePrefix` 固定 `AVF-********` |
| 上游 ID | `int64` | `cdkId` / `saleId` 均为 UUID |
| 码格式 | `SXC-…` / `GPTD-…` | `AVF-[0-9A-F]{32}` |
| CDK 报价 | `GET /gpt-direct/plans` + registry | `GET /gpt-direct/cdk-offers`（`plans` 只服务 Direct） |
| 套餐键 | registry 可含 `credit*` | generate/plans **仅** `go, plus, pro_5x, pro_20x` |
| 公开兑换 | `/api/v1/cdk/*`，result 为 GET | **`/api/public/cdk/*`**，result 为 POST |
| 设备头 | 任意，缺省 UA | `X-Redemption-Device` 必须是 UUID |
| Webhook | `X-Signature` = HMAC(secret, body) | `X-Avanfinity-Signature: v1=` + HMAC(secret, `ts + '.' + body`) |

公开兑换绝对路径不要拼成 `/api/v1/public/cdk`。新文档 `servers` 是 `/api` + path `/public/cdk/preview`。

## Provider 最小方法集

`Ping` / `Balance` / `SellablePlans` / `Issue` / `Preview·Preflight·Redeem·Result` / `ListCDKs` / `VerifyWebhook`。

禁用、选卡产品、cdk-orders 做成可选能力。新协议没有 disable path，也没有 `preferred_issuer`：选卡策略只映射为 `forceNewCard`。

`SellablePlans`：旧 = registry ∩ ACC enabled；新 = `cdk-offers` 且 `enabled && READY && salePrice != null`。不可只看 `stock`。

## 配置与数据

- 新表 `card_platform_accounts`：协议、Base、凭证、webhook_secret、`is_default`。
- P0 仍可读 `card_api_base` + `card_api_key`，当作隐式旧账户，保证旧 Key 继续能用。
- `cardplatform_cdk_codes` 必须加 `provider` + `upstream_ref TEXT`（旧 `upstream_id INTEGER` 装不下 UUID）。
- 唯一约束：`UNIQUE(code)` 保留；增加 `UNIQUE(provider, upstream_ref)`。
- 备注表、webhook 回写一律按 `(provider, upstream_ref)`，禁止用新 UUID 去更新旧整数行。

## 完整码硬约束

Issue 成功 = 完整码已写入本站库。超时先用**同一 Idempotency-Key** 重放（窗口约 2 分钟），再换键。列表与 webhook **不能**补全文。`code` 为空不得把订单标为已发货。

## Webhook

同一入口 `POST /api/v1/webhooks/cardplatform`，按头分流：

- 有 `X-Avanfinity-Signature` → 新验签（timestamp skew ≤ 300s，去重用 `X-Avanfinity-Webhook-Id`）。
- 否则走现有 `X-Signature`。

可选别名 `/api/v1/webhooks/avanfinity`，同一 handler。两套 secret 不得混用（新 secret 独立，不从 App-Secret 派生）。

事件：`openai.cdk.consumed|reserved|released|frozen|unfrozen|disabled` 回写本账户码状态；`openai.direct.completed` 对应旧 `gpt_direct.completed`。payload 在 `data.object.cdkId`。

## 分阶段

**P0** 抽 `CardProvider`，旧 client 搬家；库表加列；webhook 按头分流。默认流量不变。

**P1** 实现 Avanfinity adapter；账户 CRUD；`/ops/integration` 改成双协议卡；公开兑换按前缀分流。默认仍是旧账户。

**P2（已被绑定设计取代）** 旧设想是「新发码按优先级选一台」。现改为：新本站码 **双发预绑定**，兑换侧 failover；`credit*` 仍锁旧台单绑。详见绑定设计 P1/P2。

## 管理与自动切换

可视化：[多卡台管理与自动切换](C:\Users\onlyWjt\.cursor\projects\c-Users-onlyWjt-Documents-yer-danew-card-cdk\canvases\multi-card-failover-ops.canvas.tsx)

**管的是账户，不是每笔选台。** 卡台接入一页：每家一张卡（启用、优先级、健康、余额/库存）。站点级开关「自动切换」。代理和二级不看见卡台名。

**Legacy 原生码：兑换、查单、禁用、webhook 绝不换台**——码已经绑死发卡协议。

**新本站码：发码时就绑 A+B，不在发码阶段「选一台」；兑换才按健康切到未核销的备绑。** 旧「购卡履约按优先级试账户」不再是目标。

| 上游表现 | 切下一台 | 熔断 |
| --- | --- | --- |
| 超时 / 502 / 503 | 是 | 是（15 分钟） |
| 新台 stock=0 / WAITING_QUOTE | 是 | 否 |
| 余额不足（策略允许） | 是 | 否 |
| 403 白名单 | 是 | 否 |
| 401 密钥错 | 否 | 否 |
| 兑换失败 | 否 | 否 |

一单可以跨台拼齐（A 吐 1 张超时，剩余试 B）。每张码记自己的 provider；二级仍按 `order_no` 入库。

P1 先并排、自动切换默认关；身份和前缀兑换稳了再开。

## 布局

`/ops/integration` 一张页：出口 IP（站点级）+ 两张协议卡 + 代理换码（站点级）+ 默认账户摘要。不新开菜单。

- 发码页：只读徽章「当前默认来源」。不要每笔选台。
- 代理管理 / 代理门户：**不露出**卡台协议。二级买的是本站商品。

## 风险摘要

1. 完整码窗口约 2 分钟，过后不可恢复。
2. 新 generate **不扣套餐费**，`offers.salePrice` 不是旧 `serviceFeeUsdMinor`。
3. `credit*` 不能走新 generate。
4. ping / client 必须按协议带头，两套 `sk_` 前缀容易用错。
5. 新 result 是 POST，设备必须是 UUID。
