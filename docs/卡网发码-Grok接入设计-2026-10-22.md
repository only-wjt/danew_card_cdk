# 卡网发码接口（cardnet）接入 Grok 设计

> 日期：2026-10-22　·　状态：**已实现**（分支 `feat/cardnet-grok`）
> 前置文档：`docs/卡网发码接口设计-2026-10-17.md`（下称「原设计」）、对外接口 `docs/cardnet-api-zh.md`
> 对接方改造：dujiao-next 仓库 `docs/cdkissue-danew-cdk-Grok接入设计-2026-10-22.md`

## 0. 背景

卡台后来加了「X 订阅码」「Grok」两个产品，管理端「购买并生成」和批量充值都已支持。卡网对接这一块没跟上，
管理端「卡网对接 → 客户端 → 允许套餐」只列出 ChatGPT 档位。原因：

| # | 位置 | 问题 |
|---|---|---|
| 1 | `handler/cardnet.go` `cardnetUpstream()` | `cli.GetPlans(ctx)` 不带 product，默认只取 GPT 目录（`/gpt-direct/plans`）。X / Grok 必须带 `?product=x\|grok` 才会返回 |
| 2 | `AdminCardnetOptions` / `CardnetOverview` / `createCardnetRequest` | 有意排除 X：过滤 `IsXPremiumPlan`，发码直接 422 |
| 3 | `runCardnetIssue` / `CompleteCardnetRequest` | 发码直接用 `req.Plan`，落库直接用卡台回的 plan。没有走 Grok 的 `grok_` 前缀规则（管理端见 `cardplatform_cdk.go` 的 `GrokIssuePlan`），也没有固定 US 地区 |
| 4 | 发码前售卖性校验 | `SellableKeys()` 只来自 GPT 目录，Grok 档位一律 `PLAN_NOT_SELLABLE` |

目标：卡网可以发 **Grok** 订阅码，码落本站库，买家在本站「Grok」入口兑换、查单，和管理端发出的 Grok 码完全一致。

非目标：
- **X 订阅码不开放给卡网**：保持现有排除逻辑，并补齐 §3.1 的显式拒绝；
- 不改 GPT 档位的任何行为。已有客户端配置、已有请求的幂等哈希都不变；
- 不改公开兑换 / 查单流程，它们已经支持 `grok_` 前缀的本地码。

## 1. 决策

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | X 是否开放 | **不开放**。目录、选项、overview 都不列；发码一律 422 `PLAN_NOT_SELLABLE` | 业务决定 |
| D2 | 对卡网暴露的 Grok 档位键 | **带 `grok_` 前缀**：`grok_plus_monthly`、`grok_premium_yearly` 等 | 裸键 `premium_monthly` 和 X 同名，卡网侧没有产品信息就区分不了。本站库里 Grok 码本来就存带前缀的键，发给卡台的键也是带前缀的（`GrokIssuePlan`），三处保持一致 |
| D3 | 发码请求是否加 `product` 字段 | **不加**。档位键自带产品（`grok_` 前缀 = Grok，否则 = GPT） | 接口不变，老卡网不受影响；参数哈希不用改 |
| D4 | Grok 付款地区 | **固定 US**。`payment_country` 只能是空或 `US`，空按 `US` 处理并落库；其它值返回 422 `COUNTRY_UNSUPPORTED` | 卡台 Grok 是美元固定价，兑换时一律按 US 收单（见 `scopeGrokCatalogue`）。传了别的地区不报错就等于静默改了买家看到的承诺 |
| D5 | Grok 是否受客户端「允许地区」约束 | **不受**。`allowed_countries` 只约束 GPT | 这个开关的作用是选择 GPT 付款地区（各地区成本不同）。Grok 只有一个地区，再约束一次只会造成「客户端没勾 US 就卖不了 Grok」这种配置陷阱 |
| D6 | 每日额度 | **GPT 和 Grok 共用** `daily_code_limit`（按张数） | 额度是防 Key 泄露的兜底，不是业务配额。分产品计额度另议 |
| D7 | 旧 Grok 键（`grok_lite_*` / `grok_heavy_*` / `grok_monthly` / `grok_yearly`） | 入口处统一换成新键（`GrokIssuePlan` 已有映射），然后再做授权、哈希、落库 | 和管理端一致。卡网拿到的 overview 只会有新键，这一条只是兜底 |
| D8 | 主台不支持付款地区的协议 | 不列出 Grok 档位，发码返回 422 `PLAN_NOT_SELLABLE` | 管理端对 Grok 要求 `provider.SupportsPaymentCountry`。目前卡网可用的主台协议都满足（Avanfinity 已被 `cardnetAccountUsable` 排除），这里显式写出来做防御 |

## 2. 档位键规则

新增 `cardnetCanonicalPlan(raw string) (plan, product string, err *cardnetPlanErr)`，**所有入口统一先过这一步**：
发码、管理端保存客户端、overview 过滤。

```
p := lower(trim(raw))
1. p 以 grok_ 开头且 IsGrokPlan(p)   → product=grok, plan=GrokIssuePlan(p)     // 旧键→新键，前缀保证存在
2. IsXPremiumPlan(p)（含 x_ 前缀、裸 premium_*/basic_*）
                                    → 拒绝：PLAN_NOT_SELLABLE「X 订阅不支持卡网发码」
                                      裸 premium_monthly/yearly 的 message 追加提示「Grok 请用 grok_premium_monthly」
3. IsGrokPlan(p)（裸 plus_monthly / super_yearly / monthly …）
                                    → 拒绝：PLAN_NOT_SELLABLE「Grok 档位须带 grok_ 前缀：grok_<p>」
4. 其它                             → product=gpt, plan=p（与现状一致）
```

- 判断顺序不能换：`grok_premium_monthly` 必须先命中第 1 条（`IsXPremiumPlan` 只去掉 `x_` 前缀，不会误判，但写清楚更稳）；
- 第 3 条不自动补前缀。卡网必须用 overview 给出的键，自动补前缀会让「同一张码两个键」出现在幂等哈希和统计里；
- 发码路径里，`CardnetParamsHash` 用的是**规范化后的** plan 和 country。GPT 规范化前后一样，存量请求重放不受影响。

## 3. 改动

### 3.1 卡台目录快照：按产品拉取

现状：`cardnetUpstreamSnapshot` 一份快照包含 GPT 目录和余额，60 秒 TTL，失败不缓存。

改为分开缓存三份，各自 TTL 60 秒、失败不缓存，key 都带 `account_id`：

```go
type cardnetCatalog struct {          // 每个产品一份
    accountID int64
    plans     *cardplatform.PlansResponse
    err       error
    at        time.Time
}
var cardnetCatalogs = map[string]*cardnetCatalog{} // "gpt" / "grok"，受 cardnetSnapMu 保护
// 余额单独一份 cardnetBalanceSnap，结构同现有 balance/balErr

func cardnetPlans(ctx, acc, product string) (*cardplatform.PlansResponse, error) // GetPlans(ctx, product)，gpt 不传参
func cardnetBalance(ctx, acc) (*cardplatform.BalanceResponse, error)
```

- 按需拉取：发 GPT 码只读 gpt 目录，发 Grok 码只读 grok 目录。overview 和管理端选项读两个目录加余额；
- **Grok 目录失败不影响 GPT**：overview 照常返回 GPT 档位，Grok 标为不可用（§3.3）；
- `cardnetSnapshotWait`（8 秒）仍是单次读目录的上限。overview 要读三份时**并发**读，避免叠加到 24 秒；
- `resetCardnetUpstreamCache()` 清空全部三份；
- 老卡台会忽略 `product` 参数，返回的还是 GPT 目录。`scopeGrokCatalogue` 会把它收成空目录，即「成功但没有 Grok 档位」，可以缓存。

### 3.2 售卖档位列表（overview 与管理端选项共用）

新增 `cardnetSellable(ctx, acc) (rows []cardnetPlanRow, products map[string]cardnetProductState)`：

```go
type cardnetPlanRow struct {
    Key, Product, Label string     // Key：gpt 原样；grok 为 "grok_"+注册表裸键
    cardplatform.SellablePlan      // 服务费、sort_order、checkout_* 等
}
type cardnetProductState struct {
    Available           bool
    Message             string                      // 不可用原因
    PaymentRegions      []cardplatform.PaymentRegion
    FixedPaymentCountry string                      // grok = "US"
}
```

- GPT：`plans.SellablePlans()`，跳过 `IsXPremiumPlan`，现有逻辑原样保留；
- Grok：`GetPlans(grok).SellablePlans()`，注册表键是裸键，`Key = GrokIssuePlan(p.Key)`；`Label = GrokPlanLabel(Key)`（如「Grok Premium 月付」）。注册表里的 label 是「Premium 月付」这类不带产品名的文案，和 GPT 的 Plus 放在一起会混淆；
- Grok 地区：取 grok 目录的 `PaymentRegions`（`scopeGrokCatalogue` 固定为 `[{US, USD}]`）；
- 排序：先 GPT 后 Grok，同一产品内按 `sort_order` 再按 key；
- 主台协议不满足 `provider.SupportsPaymentCountry` 时 Grok `Available=false`，`Message="当前主台不支持 Grok 订阅码"`，不列档位（D8）。

### 3.3 `GET /api/v1/cardnet/overview`

在原响应基础上**只加字段，不改已有字段的含义**：

```json
{
  "issuable": true,
  "platform": {"account_id": 1, "name": "ZovoCard", "status": "active", "circuit": "closed", "supports_payment_country": true},
  "balance": {"balance": "100.00", "spendable_balance": "80.00", "account_reserve_amount": "20.00"},
  "plans": [
    {"key": "plus", "product": "gpt", "label": "Plus", "purchasable": true, "service_fee_usd_minor": 150,
     "sort_order": 10, "checkout_currency": "", "checkout_amount_minor": 0},
    {"key": "grok_premium_monthly", "product": "grok", "label": "Grok Premium 月付", "purchasable": true,
     "service_fee_usd_minor": 100, "sort_order": 2, "checkout_currency": "USD", "checkout_amount_minor": 3000}
  ],
  "payment_regions": [{"country": "PH", "currency": "PHP"}, {"country": "US", "currency": "USD"}],
  "products": {
    "gpt":  {"available": true, "payment_regions": [{"country": "PH", "currency": "PHP"}, {"country": "US", "currency": "USD"}]},
    "grok": {"available": true, "payment_regions": [{"country": "US", "currency": "USD"}], "fixed_payment_country": "US"}
  },
  "client": {"allowed_plans": ["plus", "grok_premium_monthly"], "allowed_countries": ["PH", "US"],
             "daily_code_limit": 200, "issued_today": 37},
  "checked_at": "2026-10-22T09:00:00Z"
}
```

| 字段 | 说明 |
|---|---|
| `plans[].product` | 新增：`gpt` / `grok`。老卡网不认这个字段也没关系，可以按 `key` 是否以 `grok_` 开头自己判断 |
| `plans` | GPT 和 Grok 的可售档位与 `client.allowed_plans` 取交集。**永远不含 X** |
| `payment_regions` | **含义不变**：仍是 GPT 的地区清单（兼容老卡网） |
| `products` | 新增：各产品是否可用、地区清单、固定地区。`available=false` 时带 `message`，比如「卡台 Grok 套餐暂不可读」 |
| `issuable` | 含义不变：主台可用且余额可读 |
| `message` | 原来只在 `issuable=false` 时出现。现在 Grok 目录读取失败但 GPT 正常时，`issuable` 仍为 true，原因写在 `products.grok.message` |

`checkout_currency` / `checkout_amount_minor` 对 Grok 是卡台下发的美元实付价，透传即可，本站不换算。

### 3.4 `POST /api/v1/cardnet/cdks/issue`

请求体不变。新的处理顺序（相对原 §5.3 的变化用 ★ 标出）：

```
1. 鉴权、Idempotency-Key 格式、JSON 解析、count 与长度校验（不变）
2. ★ plan, product, perr := cardnetCanonicalPlan(body.Plan)
      perr != nil → 422 PLAN_NOT_SELLABLE（X / 裸 Grok 键）
3. ★ country 规范化：
      product=grok：country ∈ {"", "US"} → "US"；否则 422 COUNTRY_UNSUPPORTED「Grok 只支持 US 付款」
      product=gpt ：不变（空保持空，按 PH 计）
4. 查 (client, key)：
      已存在 → 比对 CardnetParamsHash(plan, country, count)（★ 用规范化后的值）
              pending 时重新校验授权（cardnetPermitted）
      不存在 → cardnetPermitted → createCardnetRequest
5. ★ cardnetPermitted(client, plan, product, country)：
      !AllowsPlan(plan)                  → 403 PLAN_NOT_ALLOWED
      product=gpt && !AllowsCountry(c)   → 403 COUNTRY_NOT_ALLOWED
      product=grok                       → 不查地区授权（D5）
6. ★ createCardnetRequest 的售卖性校验按产品：
      主台不可用                          → 503 ISSUING_UNAVAILABLE（不变）
      grok && !SupportsPaymentCountry    → 422 PLAN_NOT_SELLABLE（D8）
      目录 = cardnetPlans(acc, product)，拿不到不拦（不变）
      grok：SellableKeys 是裸键 → 用 GrokBarePlan(plan) 去查
      gpt ：不变
      地区：gpt 走 regionSupported（不变）；grok 已在第 3 步收成 US，不再查
   建单时 req.Plan = 规范化后的 plan（Grok 带 grok_ 前缀），req.PaymentCountry = "US"
7. runCardnetIssue：
      wire plan：req.Plan 原样（Grok 已带前缀；为防御仍包一层 GrokIssuePlan，幂等）
      pref.PaymentCountry = req.PaymentCountry（Grok 为 US，所以 prefs 一定非空）
      选卡偏好 issuePrefFromAccount：Grok 也带上（与管理端发 Grok 码一致）
8. ★ 落库：Grok 的 CardnetCodeToSave.Plan = GrokIssuePlan(firstNonEmpty(it.Plan, req.Plan))
      卡台回的是裸键，不补前缀的话本站库里会存成裸 premium_monthly，查单和通知都会显示成 X
9. ★ 档位一致性校验（新，仅 Grok）：GrokIssuePlan(it.Plan) != req.Plan
      → 请求转 review，error_code=UPSTREAM_PLAN_MISMATCH，告警，返回 502
      防止卡台按别的档位发码后，把错误档位的码交给买家。
      GPT 不做：无法确认卡台对所有 GPT 档位都原样回显键，误判会让 GPT 发码整批卡在待核对
```

成功响应格式不变，Grok 示例：

```json
{
  "request_id": "CNR20261022a1b2c3d4e5f6", "status": "succeeded",
  "plan": "grok_premium_monthly", "payment_country": "US", "count": 1,
  "issued": [{"id": 5012, "code": "....", "plan": "grok_premium_monthly", "payment_country": "US", "fee_amount_minor": 100}],
  "fee_total_minor": 100, "replayed": false
}
```

错误码表新增一行：

| HTTP | error_code | 场景 |
|---|---|---|
| 502 | `UPSTREAM_PLAN_MISMATCH` | 卡台回的码档位与请求不符，已告警待人工核对（与 `UPSTREAM_COUNT_MISMATCH` 同等处理） |

已有错误码的新触发场景：`PLAN_NOT_SELLABLE`（X 键、裸 Grok 键、主台不支持 Grok）、`COUNTRY_UNSUPPORTED`（Grok 传了非 US）。

### 3.5 `POST /api/v1/cardnet/cdks/revoke`

不用改。作废按上游 id 调 `DeleteCDK`，失败再 `DisableCDK`，和产品无关。需要用测试确认卡台对 Grok 码的删除和退费与 GPT 一致（§6）。

### 3.6 管理端 review 处理（重新拉取 / 标记失败）

「重新拉取」复用 `runCardnetIssue`，自动带上第 7–9 步。`UPSTREAM_PLAN_MISMATCH` 的处理和 `UPSTREAM_COUNT_MISMATCH` 一样：
人工去卡台核对，然后「标记失败」或「重新拉取」。

### 3.7 管理端「卡网对接」页

后端 `GET /api/v1/admin/cardnet/options`：

```json
{
  "plans": [
    {"key": "plus", "product": "gpt", "label": "Plus", "service_fee_usd_minor": 150},
    {"key": "grok_premium_monthly", "product": "grok", "label": "Grok Premium 月付", "service_fee_usd_minor": 100}
  ],
  "payment_regions": [...],          // 仍是 GPT 地区
  "products": { ...同 overview... },
  "message": ""
}
```

数据来自 §3.2 的 `cardnetSellable`，不和客户端授权取交集（这里就是用来配置授权的）。

后端保存客户端（`normalizeCardnetClientInput`）：
- `allowed_plans` 每项先过 `cardnetCanonicalPlan`：旧 Grok 键换成新键；X 键和裸 Grok 键报错（「X 订阅不开放给卡网」「Grok 档位须带 grok_ 前缀」），不静默丢弃；
- 不校验「卡台当前是否可售」：卡台下架后仍允许保留，前端会标「卡台已停售」（现有行为）。

前端 `CardnetView.vue`：
- 允许套餐勾选区**按产品分组**，分「ChatGPT」「Grok」两组，组标题旁显示该组可用状态（`products.*.message`）。Grok 组提示「固定美国(USD)付款，不受允许地区限制」；
- 已授权但不在选项里的键（stale）仍然列出，按 key 前缀归组；
- 允许地区的标签改为「允许地区（仅 ChatGPT）」；
- 客户端列表的「允许套餐」列、发码请求列表、统计页的 plan 列，改用 `lib/plan.ts` 的档位文案函数（它已支持 `grok_` 前缀），不再直接显示原始键；
- 发码请求列表加「产品」筛选：`GET /admin/cardnet/requests?product=gpt|grok`，后端按 plan 是否以 `grok_` 开头过滤，不需要加列。

### 3.8 通知与统计

- 卡网告警（review、额度 80%、作废失败）的文案带上 plan 文案（`gptPlanLabel` 已支持 Grok）；
- `AdminCardnetStats` 按 plan 分组，Grok 自然会单独成行，不用改 SQL。前端补产品文案即可。

## 4. 不需要改的地方（已核对）

| 逻辑 | 原因 |
|---|---|
| 公开兑换路由 | 本地行有 `fulfilled_account_id`，按台路由，和产品无关 |
| 公开兑换页 | `RechargeView` 按卡台预览回的 product 分流到 Grok 流程（sso 登录态，不产预检票） |
| 公开查单 / 成功通知 | `cardProductPlan` / `gptPlanLabel` 认 `grok_` 前缀 |
| webhook 回写 | 按 `upstream_id` 回写，和产品无关 |
| 代理拦截 | 卡网码不挂代理（原设计 D3） |
| 超时找回 | 卡网路径本来就不用 `SyncUpstreamFullCodes`，只靠上游幂等键重放。管理端不对 Grok 自动找回的原因（裸键同名）在这里不存在 |

## 5. 兼容与上线顺序

1. **本站先上线**。这时没有客户端勾选 Grok 档位，overview 的 `plans` 不会出现 Grok，老卡网完全无感（新增的字段会被忽略）；
2. dujiao-next 上线 Grok 支持（见对接方文档）；
3. 管理端给卡网客户端勾选 Grok 档位，卡网后台就能看到并配置商品。

回滚：取消勾选 Grok 档位即可。已发出的 Grok 码不受影响，同键重放仍能拿回码（已成功的请求不重新校验授权）。

老卡网如果在第 3 步之前就拿到了 Grok 档位（误勾），按它现在的逻辑：要么不认这个键，要么带着 PH 去发码，收到 422 `COUNTRY_UNSUPPORTED`。都是明确拒绝、未发码，不会产生错码。

## 6. 测试要点

在 `cardnet_test.go` 的 fake 卡台上加 `?product=grok` 分支：注册表返回裸键，定价表返回 `grok_` 前缀键，`payment_regions` 任意。

- **目录**：overview 同时列出 GPT 和 Grok，Grok 键带前缀、`product=grok`、label 带「Grok」，`products.grok.fixed_payment_country=US`；永远不含 X；未授权的 Grok 档位不出现；
- **Grok 目录失败**：fake 对 `product=grok` 返回 500，overview 仍有 GPT 档位，`products.grok.available=false`，`issuable=true`；
- **发码**：`grok_premium_monthly` 空地区 → 卡台收到 `plan=grok_premium_monthly`、`payment_country=US`。本地码 plan 是 `grok_premium_monthly`、`payment_country=US`、`issue_source=cardnet`；
- **地区**：Grok + `PH` → 422 `COUNTRY_UNSUPPORTED`，没有调卡台；Grok + `US` 和 Grok + 空是同一个请求（同键重放不报 `IDEMPOTENCY_KEY_REUSED`）；客户端 `allowed_countries=[PH]` 时仍能发 Grok；
- **键规范化**：`grok_lite_monthly` 规范成 `grok_plus_monthly`，授权和落库都用新键；`premium_monthly` / `x_basic_monthly` → 422，message 提示 X 不开放；`plus_monthly` → 422，提示加前缀；
- **售卖性**：Grok 目录里没有的档位 → 422 `PLAN_NOT_SELLABLE`；GPT 目录里的 `plus` 不受 Grok 目录影响；
- **档位不一致**：fake 回 `plan=premium_yearly`，而请求是 `grok_premium_monthly` → review + `UPSTREAM_PLAN_MISMATCH` + 502；
- **额度**：GPT 和 Grok 共用 `daily_code_limit`；
- **作废**：Grok 码未使用 → 删除并退费；已兑换 → `CONSUMED`；
- **管理端**：保存客户端时 X 键报错、旧 Grok 键换成新键；options 分产品返回；
- **回归**：GPT 全部现有用例不变，尤其是 `TestCardnetDefaultCountrySemantics` 和 `TestCardnetReplayAfterPermissionRevoked`；
- **端到端**：卡网发出的 Grok 码在本站兑换页能识别为 Grok，粘 sso 登录态可以兑换，查单显示「Grok Premium 月付」。
