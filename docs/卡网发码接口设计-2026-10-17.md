# 卡网发码接口（cardnet）设计

> 日期：2026-10-17　·　状态：**待确认后实现**（本文只定设计，不改代码）
> 对接方：dujiao-next 卡网（card.danew.cc）。对接方改造见该仓库 `docs/cdkissue-danew-cdk-对接设计.md`。
> 前提：**双绑后续下线，本接口不考虑双绑**，只向主卡台发码。

## 0. 背景与目标

卡网现在用自己的 ZovoCard Key 直接调卡台 `POST /gpt-direct/cdks`，码不进本站库，导致：

- 公开查单（`lookupOneCDK`）只认本站表，卡网发的码一律「未找到该卡密」；
- 兑换时本地查不到码，路由回落到 `legacy_card_platform_account_id`，主台变更后会打错台；
- 卡台列表/订单接口按 Key 隔离，本站管理端同步、对账、卡健康都看不到这批码。

目标：本站提供一个**只给卡网用**的服务端发码接口。由本站用自己的主台 Key 向卡台发码，并按管理端发码同样的方式落库（`code_kind=legacy`、`fulfilled_account_id=主台`）。之后查单、兑换路由、webhook 回写、通知、统计都自然覆盖。

非目标：不改公开兑换/查单流程；不给卡网做计费账户；历史直发码回填另做（§8）。

## 1. 决策

| # | 决策 | 默认 |
|---|---|---|
| D1 | 是否向卡网计费 | **不计费，只记账**：每张码记录上游服务费，管理端按客户端/日期汇总 |
| D2 | 发到哪个卡台 | **主台**（`PrimaryCardPlatformAccount`），码上记 `fulfilled_account_id`，之后换主台也不影响已发码的兑换路由 |
| D3 | 是否挂到代理名下 | **不挂**（`assigned_agent_user_id=0`），否则会被 `block_public_redeem` 拦截，买家无法在公开页兑换 |
| D4 | 单次最多张数 | **200**，与卡台单次上限、卡网分片一致 |
| D5 | 同步还是异步 | **同步**：一次请求 = 一次卡台批量发码（卡台整批事务），handler 内完成；超时/5xx 由卡网用同一个键重试，本站用同一个上游幂等键重放 |

## 2. 流程

```
买家在卡网付款
   │
卡网发货任务 ──POST /api/v1/cardnet/cdks/issue  (Idempotency-Key: dj-...)──▶ 本站
   │                                            1. 按 (client, key) 查/建请求行（幂等）
   │                                            2. 占用租约
   │                                            3. 主台 IssueCDKs(plan, count, idem="cn-{client}-{request_id}")
   │                                            4. 落库 cardplatform_cdk_codes + 请求行 succeeded
   │◀──── 200 + 完整码 ／ 5xx 结果待定（卡网同键重试，本站同上游键重放）────┘
   │
买家拿码到 cdk.danew.cc 兑换 / 查单（本站库里有记录，按 fulfilled_account_id 路由）

卡网退款 ──POST /api/v1/cardnet/cdks/revoke──▶ 本站删码退费（失败则停用）
```

## 3. 鉴权与客户端

### 3.1 表 `cardnet_clients`

不复用代理账号：代理体系带易支付下单、代理定价、`block_public_redeem`，卡网都不需要。

```sql
CREATE TABLE IF NOT EXISTS cardnet_clients (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  key_prefix TEXT NOT NULL,                    -- 展示用，前 16 位
  key_hash TEXT NOT NULL UNIQUE,               -- sha256，与 HashAgentAPIKey 同法
  status TEXT NOT NULL DEFAULT 'active',       -- active | disabled
  allowed_plans TEXT NOT NULL DEFAULT '',      -- 逗号分隔；空 = 不允许（必须显式配置）
  allowed_countries TEXT NOT NULL DEFAULT '',  -- 逗号分隔；空 = 只允许默认地区
  daily_code_limit INTEGER NOT NULL DEFAULT 200, -- 每自然日（UTC+8）上限，0 = 禁止
  ip_allowlist TEXT NOT NULL DEFAULT '',       -- 逗号分隔；空 = 不限
  last_used_at DATETIME,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

- Key：`cn_live_` + 32 字节随机 hex，只在创建/轮换时展示一次；
- `allowed_plans` 默认空，`daily_code_limit` 兜底：Key 泄露时能发的码有限；
- IP 白名单取 `c.ClientIP()`（已按 Cloudflare 真实 IP 处理）。

### 3.2 `CardnetAuthMiddleware`

只接受 `Authorization: Bearer cn_live_...`；校验 Key、`status=active`、IP 白名单；`c.Set("cardnet_client_id", id)`；限流参照 `AgentRateLimit`，默认 120 rpm。

### 3.3 部署

- 路由前缀 `/api/v1/cardnet/`，不能被 OpenResty 的 admin 拦截规则命中；
- Cloudflare 对 `/api/v1/cardnet/*` Bypass cache。

## 4. 接口契约

失败响应统一 `{"error_code": "...", "message": "..."}`。HTTP 状态码语义（卡网据此决定是否重试）：

| HTTP | 含义 | 卡网处理 |
|---|---|---|
| 200 | 成功 | 交付 |
| 400 / 401 / 403 / 404 / 422 | 明确拒绝，**未发码、未扣费** | 停止，交管理员（可换新键重发） |
| 409 | 同一个键正在被另一请求处理 | 同一个键稍后重试 |
| 429 | 限流 | 同一个键稍后重试 |
| 5xx | 结果待定（可能已发码） | **同一个键**重试 |

> 「同一个键、参数不同」用 **422 `IDEMPOTENCY_KEY_REUSED`**，不能用 409：卡网把 409 当作可重试，会一直重试下去。

### 4.1 `GET /api/v1/cardnet/overview`

```json
{
  "issuable": true,
  "platform": {"account_id": 1, "name": "ZovoCard", "status": "active", "circuit": "ok",
               "supports_payment_country": true},
  "balance": {"balance": "332.40", "spendable_balance": "312.40", "account_reserve_amount": "20.00"},
  "plans": [
    {"key": "plus", "label": "Plus", "purchasable": true, "service_fee_usd_minor": 150, "sort_order": 10}
  ],
  "payment_regions": [{"country": "PH", "currency": "PHP"}, {"country": "US", "currency": "USD"}],
  "client": {"allowed_plans": ["plus", "pro_20x"], "allowed_countries": ["PH", "US"],
             "daily_code_limit": 200, "issued_today": 37},
  "checked_at": "2026-10-17T09:00:00Z"
}
```

- 数据来自主台 `GetPlans` + 余额接口，`plans` 与 `allowed_plans` 取交集、只保留 `SellableKeys`；
- `issuable=false`：主台未配置、停用或熔断中；
- 结果缓存 60 秒。

### 4.2 `POST /api/v1/cardnet/cdks/issue`

请求头 `Idempotency-Key`（必填，1–128 位，`[A-Za-z0-9._:-]`）。

```json
{
  "plan": "plus",
  "count": 1,
  "payment_country": "PH",
  "external_order_no": "DJ20261016100204767878",
  "external_ref": "item:1533:chunk:0"
}
```

| 字段 | 说明 |
|---|---|
| `plan` | 必填，须在 `allowed_plans` 且主台可售 |
| `count` | 1–200 |
| `payment_country` | 可选，空 = 默认地区；须在 `allowed_countries`，且主台支持指定地区 |
| `external_order_no` / `external_ref` | 可选，仅用于检索与审计，不参与幂等 |

**幂等**（键作用域 = 客户端）：

1. `(client_id, key)` 不存在 → 校验参数与额度，新建请求行；
2. 已存在且 `plan/count/payment_country` 相同 → 已成功则直接返回原码（`replayed=true`）；未成功则继续执行（见 §5）；
3. 已存在但参数不同 → 422 `IDEMPOTENCY_KEY_REUSED`。

**成功 200**：

```json
{
  "request_id": "CNR20261017a1b2c3d4",
  "status": "succeeded",
  "plan": "plus",
  "payment_country": "PH",
  "count": 1,
  "issued": [
    {"id": 4821, "code": "GPTD-AAAA-BBBB-CCCC-DDDD", "plan": "plus",
     "payment_country": "PH", "fee_amount_minor": 150}
  ],
  "fee_total_minor": 150,
  "replayed": false
}
```

`id` 是本站 `cardplatform_cdk_codes.id`，作废接口用它（不暴露上游 id）。

**错误码**：

| HTTP | error_code | 场景 |
|---|---|---|
| 400 | `INVALID_PARAMS` | 缺字段、count 越界、键格式错 |
| 401 | `INVALID_API_KEY` | Key 无效或客户端停用 |
| 403 | `IP_NOT_ALLOWED` / `PLAN_NOT_ALLOWED` / `COUNTRY_NOT_ALLOWED` | 客户端无权限 |
| 403 | `DAILY_LIMIT_EXCEEDED` | 超当日额度（不用 429，避免卡网无限重试） |
| 422 | `PLAN_NOT_SELLABLE` | 主台未开放该档位 |
| 422 | `COUNTRY_UNSUPPORTED` | 主台不支持指定地区 |
| 422 | `IDEMPOTENCY_KEY_REUSED` | 同键不同参 |
| 422 | `UPSTREAM_REJECTED` | 卡台明确拒绝（余额不足等），`message` 带卡台原文 |
| 409 | `REQUEST_IN_FLIGHT` | 同一个键并发调用 |
| 502 | `UPSTREAM_COUNT_MISMATCH` | 卡台返回张数不符，已告警待人工 |
| 503 | `ISSUING_UNAVAILABLE` | 主台未配置/熔断 |
| 503 | `UPSTREAM_PENDING` | 调卡台超时/5xx，结果待定 |

### 4.3 `POST /api/v1/cardnet/cdks/revoke`

卡网退款后作废未使用的码。

```json
{"ids": [4821, 4822], "reason": "order_refunded", "external_order_no": "DJ2026..."}
```

```json
{"revoked": [4821], "failed": [{"id": 4822, "reason": "CONSUMED", "message": "卡台：CDK 已使用"}]}
```

- 每次最多 100 个；只能作废本客户端发出的码（`cardnet_client_id` 匹配），否则 `NOT_FOUND`；
- 处理：主台 `DeleteCDK`（未使用的购买码会退回服务费）→ 失败且非「已使用」时退回 `DisableCDK`；成功后本地 `status` 改为 `refunded` / `disabled`；
- 卡台拒绝（已使用、已预占）→ `failed`，`reason` 取 `CONSUMED` / `RESERVED` / `UPSTREAM_ERROR`；
- 已作废的码再次作废视为成功（幂等）；
- 与兑换的并发由卡台保证：卡台只允许删除/停用 `unused` 码。

### 4.4 `GET /api/v1/cardnet/cdks?ids=...`（二期，可选）

返回码状态（`unused | reserved | consumed | disabled | refunded`）供卡网订单页展示「已使用」。一期不做。

## 5. 发码执行

### 5.1 表 `cardnet_issue_requests`

```sql
CREATE TABLE IF NOT EXISTS cardnet_issue_requests (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  request_id TEXT NOT NULL UNIQUE,          -- CNR + 日期 + 随机
  client_id INTEGER NOT NULL,
  idempotency_key TEXT NOT NULL,
  params_hash TEXT NOT NULL,                -- sha256(plan|count|payment_country)
  plan TEXT NOT NULL,
  payment_country TEXT NOT NULL DEFAULT '',
  count INTEGER NOT NULL,
  account_id INTEGER NOT NULL,              -- 建单时固化的主台；重试必须打同一台
  upstream_idem_key TEXT NOT NULL,          -- cn-{client_id}-{request_id}
  external_order_no TEXT NOT NULL DEFAULT '',
  external_ref TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL,                     -- pending | succeeded | failed | review
  fee_total_minor INTEGER NOT NULL DEFAULT 0,
  error_code TEXT NOT NULL DEFAULT '',
  error_message TEXT NOT NULL DEFAULT '',
  attempts INTEGER NOT NULL DEFAULT 0,
  lease_until DATETIME,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  completed_at DATETIME,
  UNIQUE(client_id, idempotency_key)
);
```

`account_id` 在建单时固化：处理中途站长切换主台，重试仍打原来那台，否则会在新台再买一批。

### 5.2 `cardplatform_cdk_codes` 加列

| 列 | 说明 |
|---|---|
| `issue_source TEXT DEFAULT ''` | `admin` / `agent_order` / `cardnet` |
| `cardnet_client_id INTEGER DEFAULT 0` | 作废时校验归属 |
| `cardnet_request_id INTEGER DEFAULT 0` | 重放时按请求取回码 |
| `external_order_no TEXT DEFAULT ''` | 管理端按卡网订单号查码 |

### 5.3 handler 执行步骤

```
1. 鉴权、参数校验
2. 事务：按 (client_id, key) 查行
     不存在：校验当日额度（同事务内 SUM(count)），插入 pending 行
     存在：比对 params_hash
3. status=succeeded → 按 cardnet_request_id 查码返回（replayed）
   status=failed    → 返回原错误（422）
   status=review    → 502 UPSTREAM_COUNT_MISMATCH
4. 占用租约：UPDATE ... SET lease_until=now+90s, attempts=attempts+1
             WHERE id=? AND status='pending' AND (lease_until IS NULL OR lease_until<now)
   占用失败 → 409 REQUEST_IN_FLIGHT
5. 用 account_id 的客户端调 IssueCDKs(plan, count, upstream_idem_key, pref{PaymentCountry, 本站选卡偏好})
   （请求上下文脱离客户端连接，独立 60s 超时：客户端断开不能中断一笔可能已扣费的发码）
6. 结果：
   成功且张数一致 → 事务内逐张 SaveCardplatformCDKCodeForAccount(..., account_id, country)
                    + 补写 issue_source/cardnet_* 列 + 请求行 succeeded → 200
   成功但张数不符 → 请求行 review + Telegram 告警 → 502
   卡台 4xx 明确拒绝 → 请求行 failed（error_code=UPSTREAM_REJECTED）→ 422
   超时 / 5xx / 429 / 409 → 释放租约，保持 pending → 503 UPSTREAM_PENDING
   落库失败 → 释放租约，保持 pending → 503（下次同键重放取回同一批码再落库）
```

要点：

- 上游幂等键 `cn-{client_id}-{request_id}` 在请求行生命周期内不变，卡网任意次重试都只会在卡台重放同一批码；
- 不需要后台 worker：重试由卡网队列驱动（它本来就会用同一个键重试，且有扫描兜底）；
- 超时后不使用管理端的 `SyncUpstreamFullCodes` 找回：上游幂等重放已经足够，而且同步全量码会把别的码误算进来；
- 主台返回的码只有前缀、没有完整码时（`code` 为空）按「张数不符」处理。

### 5.4 `review` 的人工处理

管理端请求详情页提供：

- 「重新拉取」：用同一个上游幂等键再调一次，张数对了就转 `succeeded`；
- 「标记失败」：人工确认卡台没扣费，或已在卡台手动作废后，转 `failed`，卡网可换新键重发。

## 6. 管理端

新增「卡网对接」页：

- **客户端**：新建、停用、轮换 Key（只展示一次）、编辑允许套餐/地区、每日额度、IP 白名单；
- **发码请求**：按客户端、状态、卡网订单号、时间筛选；详情列出码与本地状态；`review` 的处理按钮见 §5.4；
- **CDK 列表**：现有本站码列表增加 `issue_source` 筛选与「卡网订单号」列；
- **统计**：按客户端、日期汇总张数与上游服务费（D1）；
- 所有写操作记 `admin_audit_logs`。

告警（复用 `internal/notify/telegram.go`）：请求进入 `review`；单日发码达到额度 80%；作废出现 `UPSTREAM_ERROR`。

## 7. 对现有逻辑的影响

| 逻辑 | 影响 |
|---|---|
| 公开兑换路由 | 码有本地行，`CardPlatformAccountForLegacyCode` 按 `fulfilled_account_id` 路由，无需改动 |
| 公开查单 | 读到本地行，未兑换显示「未使用」；webhook `applyCDKStatusFromWebhook` 按 `upstream_id` 回写 consumed，无需改动 |
| 代理拦截 | 不挂代理，`guardAgentAssignedCDK` 放行 |
| 成功通知 | `notifyGPTSuccess` 能读到本地套餐与地区 |
| 管理端发码 / 代理购卡 | 不变（本接口不复用 `CardPlatformIssueCDKs` handler，只复用落库函数） |

## 8. 历史直发码回填（可选，独立）

卡网此前直发的码可以一次性导入，修好它们的查单：卡网导出 `(provider_cdk_id, code, plan, payment_country)`，用现有 `POST /admin/cardplatform/cdks/store` 指定卡网用的 ZovoCard 账户 `account_id` 导入。前提：该账户已在本站「卡台账户」中配置。注意卡台列表/订单接口按 Key 隔离，本站 Key 看不到卡网 Key 发的码的订单，对账类功能对这批历史码仍不完整。

## 10. 测试要点

- 幂等：同键重放返回同一批码；同键不同参 422；同键并发只有一个调用卡台，另一个 409；
- 超时：模拟卡台超时 → 503；同键重试 → 用同一个上游键，卡台重放，本地只落一批；
- 落库失败：卡台成功但本地写失败 → 503；重试后落库成功、不重复；
- 明确拒绝：卡台余额不足 → 422 且请求 `failed`；换新键可重发；
- 张数不符 → `review` + 告警，卡网拿不到部分码；
- 额度：并发请求不能突破 `daily_code_limit`；
- 主台切换：pending 请求重试仍打原 `account_id`；
- 作废：未使用 → 删除退费；已兑换 → `CONSUMED`；他人客户端的 id → `NOT_FOUND`；
- 回归：发出的码在公开页可预览、兑换，查单显示「未使用」→ 兑换后「已使用」。
